# Marine VMS

Судовой регистратор. Камеры на мостике, палубе, трапе и в машинном отделении смотрят постоянно, а файл появляется только когда выполняется правило: движение, зона, скорость судна, расписание, принятая вахта. До и после события в клип попадает короткий запас кадров.

Пульт открывается на этом компьютере: [http://127.0.0.1:8080](http://127.0.0.1:8080). Та же страница без камер публикуется на [GitHub Pages](https://gaszapros.github.io/marine-vms/). Сеть судна и чужие камеры наружу не выставляются.

## Запуск

Нужен обычный Python для Windows. Подсистема Linux не используется.

```powershell
.\run.ps1
```

Скрипт создаёт `.venv`, ставит зависимости и поднимает пульт на порту 8080. Если порт занят: `$env:PORT = "8090"; .\.venv\Scripts\python.exe -m app`.

## Как устроена демонстрация

Четыре имитатора уже заведены в базу:

| Камера | Когда появляется файл |
| --- | --- |
| Трап | Вахта принята и в кадре проход |
| Палуба | То же движение, но только если скорость меньше 3 узлов |
| Мостик | Человек в зоне пульта |
| Машинное | Крупная аномалия. Движение стрелки прибора файл не создаёт |

Кнопка «Ход в море» ставит 14 узлов: палубное правило перестаёт открывать новые клипы, трап продолжает. «Стоянка» возвращает 0,3 узла. «Вахта снята» обрывает запись.

Журнал хранит причину срабатывания. «Смотреть» проигрывает клип, «Файл» отдаёт AVI, CSV забирает журнал. Готовый клип уходит в закрытый репозиторий, релиз `recordings`, и удаляется с этого компьютера.

## Свои камеры

В пульте: RTSP-адрес, номер веб-камеры (`0`) или путь к файлу. Имитаторы: `bridge`, `deck`, `gangway`, `engine`.

Правило собирается из условий. «Все сразу» — логическое И, «любое» — ИЛИ. У движения есть порог в процентах кадра и необязательная зона (доли от 0 до 1). Расписание понимает окно через полночь, дни `0`–`6` с понедельника.
